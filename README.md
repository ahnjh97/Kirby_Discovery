### 맵 렌더링 최적화

**문제**

- 대형 맵을 공간별로 컬링하려면 메쉬를 분할해야 하며, 분할 경계에 걸친 삼각형의 중복 저장과 누락을 피해야 했습니다.
- 기존 컬링 분기는 자식이 없는 말단 노드를 화면 밖 판정보다 먼저 처리해, 검사에서 제외할 노드도 렌더링할 수 있었습니다.

**해결**

- 삼각형의 세 정점이 같은 Octant에 속하면 해당 자식으로 내려보내고, 경계를 가로지르면 부모 노드에 남겼습니다.
- 노드 꼭짓점과 확장 반지름을 이용한 기존 절두체 검사 결과에 따라 전체 메쉬를 그리거나, 부모에 남은 메쉬를 그린 뒤 자식을 재검사하도록 구성했습니다.
- 이후 코드 개선에서 검사에 통과한 꼭짓점이 없으면 먼저 반환하도록 순서를 수정해, 말단 노드에도 제외 조건을 적용했습니다.

**결과**

- 경계 삼각형을 여러 자식에 중복 배치하지 않고, 부모와 자식의 메쉬를 나누어 렌더링하도록 구성했습니다.
- 기존 절두체 검사에서 화면 밖으로 분류된 말단 노드가 렌더링되는 분기를 제거했습니다. 프레임 성능 개선 폭은 측정하지 않았습니다.

### 맵 제작 도구

**문제**

- 팀원이 오브젝트와 지형을 배치하고 수정한 결과를 게임에서 다시 사용할 수 있는 제작 흐름이 필요했습니다.

**해결**

- ImGui로 편집 대상을 선택하고 ImGuizmo로 위치·회전·크기를 조절하는 맵 툴을 제작했습니다.
- 배치한 맵 데이터를 저장하고 불러오는 기능을 연결했습니다.

**결과**

- 팀 전체가 맵 툴에서 배치·수정·저장한 데이터를 레벨 제작에 활용했습니다.

### 사자 보스 전투 시스템

**문제**

- 공격 패턴마다 동작과 타격 시점이 달라, 애니메이션에 맞춰 판정을 활성화하고 같은 타격 이벤트의 반복 실행을 구분해야 했습니다.

**해결**

- 보스 상태에 따라 공격 패턴과 애니메이션을 전환했습니다.
- 애니메이션별로 발동 진행률·실행 여부·판정 종류를 저장하고, 현재 진행률에 도달한 미실행 항목의 히트박스를 활성화했습니다.
- 처리한 항목의 실행 플래그를 켜고, 해당 애니메이션을 다시 사용할 때 초기화했습니다. 현재 검사는 호출 한 번에 항목 하나를 처리합니다.
- 보스 전방 벡터와 플레이어 방향 벡터의 외적 Y 성분으로 좌우를 판별했습니다.

**결과**

- 패턴별 타격 시점을 애니메이션 진행률에 연결하고, 이미 실행한 타격 항목이 같은 재생 중 다시 활성화되지 않도록 처리했습니다.

### 사자 보스 애니메이션 및 연출

**문제**

- 보스가 공격하는 중에도 얼굴·입의 피격 반응과 플레이어를 바라보는 시선이 필요했습니다.

**해결**

- 기본 동작을 갱신한 뒤, 부분 애니메이션의 유효 Bone 집합에 포함된 채널만 추가로 갱신했습니다.
- 선택한 Bone의 결합 행렬을 다시 계산해 부분 동작을 반영했습니다.
- 눈동자 UV 오프셋을 조절해 플레이어를 추적하는 시선을 표현했습니다.

**결과**

- 기본 공격 동작을 유지하면서 지정한 부위에 피격 동작을 적용하고, 시선 연출을 별도로 제어했습니다.

### 오브젝트 풀링

**문제**

- 보스 패턴에서 다수의 바위와 파편이 반복 등장하므로, 패턴마다 객체를 새로 생성하는 비용을 줄일 필요가 있었습니다.

**해결**

- 바위와 파편을 각각 400개 사전 생성하고, 패턴별 인덱스로 사용할 객체를 선택했습니다.
- 재사용할 때 위치·크기·회전·숨김 상태·타이머를 다시 설정하고, 패턴에 따라 방향과 낙하 속도를 조절했습니다.
- 숨김 상태가 된 바위는 활성 인덱스 목록에서 제거하되, 객체는 보관해 다시 사용했습니다.

**결과**

- 사전 생성한 객체로 바위·파편 연출을 반복 실행하도록 구성했습니다. 비활성 객체를 자동 탐색하는 범용 풀 대신, 정해진 패턴의 인덱스로 재사용하는 방식입니다.
